# Restricted input data policy

This public repository intentionally excludes every subject-, case-, ROI-, image-, and prediction-level dataset.

## Excluded inputs

The audited source packages contained files with names such as:

- `ROI_level_features.csv` and `ROI_level_features_used.csv`;
- `Case_level_features.csv` and `Case_level_features_used.csv`;
- `case_metadata.csv`, `metadata.csv`, and `metadata_used.csv`;
- original or cropped UV-PAM images and H&E images.

These files are not part of the public release. Renaming, pseudonymizing, or replacing case labels does not convert a restricted feature table into a public-safe artifact; the feature vectors and label associations remain derived human-specimen data.

## Excluded outputs

The public release also excludes:

- out-of-fold prediction rows and scores;
- case-level aggregation checks;
- case-level feature-distribution or box-plot data;
- ROI dimension audits containing ROI records or filenames;
- any generated table that retains case IDs, ROI IDs, filenames, pathologies linked to individual rows, or individual feature values.

## Expected private layouts

With approved access, `scripts/analysis_script.py` expects:

```text
data/ROI_level_features.csv
data/Case_level_features.csv
```

The ROI table schema includes `case_id`, `pathology`, ROI/QC columns, and the quantitative feature columns documented in `feature_definitions.csv`. The case table contains one case-level row generated by arithmetic averaging of ROI features within each case.

With approved access, `scripts/run_feature_based_reanalysis.py` expects:

```text
inputs/Case_level_features_used.csv
inputs/ROI_level_features_used.csv
inputs/feature_extraction_parameters.json
```

The feature-extraction script expects a restricted `metadata.csv` plus the corresponding ROI images under `roi_images/`.

All these locations and known restricted filenames are blocked by `.gitignore`. Before any future GitHub commit or release, repeat the identifier and data-leakage scan described in `MANIFEST.md`.
